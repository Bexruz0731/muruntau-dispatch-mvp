# Конвейерная лента и бесконечный цикл машин — design

Дата: 2026-08-12
Статус: утверждено пользователем, готово к планированию

## Контекст и цель

Сейчас маршрут машины одноразовый: `ENTERING → TO_LOAD → LOADING → EXITING → DONE` — машина "уезжает" через абстрактную точку `EXIT_POINT` и исчезает со сцены, а отчёт по топливу логирует одну строку с крошечными цифрами (доли км/литра — потому что это всего одна поездка внутри короткой демо-сессии).

Меняем на реалистичную модель карьера: снаружи воронки стоит конвейерная лента с бункером, куда машина сваливает груз, разворачивается и едет обратно в карьер за новой партией — **бесконечно**, без исчезновения со сцены. Отчёт по топливу при этом переходит от "одна строка на разовую поездку" к "строка на каждые 5 завершённых рейсов" (условная смена), чтобы цифры в отчёте были реалистичного масштаба, а не смешными долями.

## Точки и геометрия

- `ENTRY_POINT` — без изменений, ворота карьера (радиус ~26, чуть внутри верхней кромки).
- `EXIT_POINT` **удаляется**, вместо него — `BELT_POINT`: новая точка **за пределами** воронки (радиус ~38, `> PIT_TOP_RADIUS=30`) — там физически стоит бункер и лента. `terrainHeightAt`/`groundPosition` уже отдают плоскую землю (y=0) для радиуса ≥ 30, специальной поддержки рельефа не требуется.
- Новый компонент сцены `src/components/scene/Belt.jsx`: статичная конструкция у `BELT_POINT` — бункер (тёмный стальной короб/усечённая пирамида со светящейся кромкой, тот же язык, что у `LoadPointMarker`) + наклонный конвейерный жёлоб (вытянутый бокс) с несколькими тонкими светящимися полосками, которые непрерывно "едут" вдоль жёлоба через `useFrame` (петля по модулю смещения) — постоянная фоновая анимация, не привязанная к конкретному моменту разгрузки конкретной машины.

## Конечный автомат — бесконечный цикл

```
ENTERING → TO_LOAD → LOADING → EXITING → UNLOADING → RETURNING → ENTERING → ... (без остановки)
```

- `EXITING` теперь целится в `BELT_POINT` (было — `EXIT_POINT`), длительность — из существующего `TRAVEL_DURATION_RANGE`.
- `UNLOADING` (новая фаза): машина стоит у бункера; кузов покадрово наклоняется вверх и обратно (как самосвальный кузов) — тот же визуальный язык, что прогрессбар `LOADING`, но короче (~3-5 сек, новый `UNLOADING_DURATION_RANGE`).
- `RETURNING` (новая фаза): зеркало `TO_LOAD` — едет `BELT_POINT → ENTRY_POINT`, использует `TRAVEL_DURATION_RANGE`. По завершении — сразу `ENTERING` (новый круг, диспетчер снова выбирает точку погрузки через `decideTarget`, т.к. очереди могли измениться).
- `DONE` полностью убирается из автомата. Спавн/деспавн тоже убирается: фиксированный парк создаётся один раз при `startSimulation()` (текущий стартовый пакет `MIN_ACTIVE_TRUCKS` становится просто `FLEET_SIZE`), машины никогда не покидают `trucks` и не добавляются позже — `MIN_ACTIVE_TRUCKS`/`MAX_ACTIVE_TRUCKS`/`SPAWN_PAUSE_RANGE`/`nextSpawnAt`-логика удаляется как ненужная.
- Аномалии не меняются: `seededAnomaly` присвоен машине один раз при создании и действует все её будущие рейсы (реалистично — постоянная неисправность). `detectAnomaly` продолжает пересчитываться каждый тик как раньше.

## Топливо и пробег на новых фазах

- Расход топлива — без изменений, только `TO_LOAD`/`LOADING` (правило ТЗ не трогаем).
- Пробег — раньше накапливался в `TO_LOAD`/`EXITING`; теперь дополнительно и в `RETURNING` (это тоже реальное движение с грузом или без). `accrueFuelAndDistance` в `fuel.js`: условие пробега расширяется до `TO_LOAD || EXITING || RETURNING`.
- `UNLOADING` не расходует топливо и не считается пробегом (машина стоит) — как и `LOADING` для пробега.

## "Смена" вместо разовой поездки

- Новая константа `LAPS_PER_SHIFT = 5`. Рейс (`lapsCompletedThisShift`) засчитывается при завершении `UNLOADING` (груз физически сдан).
- Каждый 5-й рейс: в `sessionLog` добавляется запись с накопленными за эти 5 рейсов `distanceThisShift`/`fuelConsumedThisShift` (реалистичные, некрошечные цифры), статус — как и раньше, `'завершила смену'` (текст уже семантически верен, менять не нужно). Сразу после записи `distanceThisShift`/`fuelConsumedThisShift`/`movingMs` обнуляются — начинается накопление следующей смены, машина при этом не останавливается и не выпадает из сцены.
- При том же событии (каждая 5-я смена) `fuelLevel` **пополняется до полного бака** (`FUEL_TANK_CAPACITY_L`) — имитация дозаправки при пересменке, чтобы на длинном демо-прогоне уровень топлива не залипал в 0 навсегда.

## Панель диспетчера

- `PHASE_LABELS` пополняется: `EXITING: 'едет на ленту'`, `UNLOADING: 'разгружается'`, `RETURNING: 'возвращается в карьер'`.
- Список "Точки погрузки" получает дополнительную строку "Лента" с очередью (сколько машин сейчас в `EXITING`+`UNLOADING`) — тот же визуальный паттерн (`statusColorForQueue`), для симметрии с точками погрузки.

## Файловая структура (затрагиваемые файлы)

```
src/simulation/
  constants.js       // EXIT_POINT -> BELT_POINT
  store.js            // FSM: UNLOADING/RETURNING, убрать DONE/спавн, LAPS_PER_SHIFT + сброс/дозаправка
  fuel.js               // accrueFuelAndDistance: пробег + RETURNING
components/scene/
  Belt.jsx             // NEW — бункер + лента с анимацией
  Truck.jsx             // анимация наклона кузова на UNLOADING; доворот по курсу тоже на RETURNING
  CareerScene.jsx / MapPage.jsx  // подключить <Belt/>, MOVING_PHASES + RETURNING
components/
  DispatcherPanel.jsx  // PHASE_LABELS, строка "Лента" в очередях
```

## Вне рамок этого изменения

- Реальное подключение локального AnythingLLM (у пользователя уже поднят сервер с документами) — отдельная задача, не требует брейнсторминга, только конфигурация `.env` и проверка.
- Визуальная очередь машин на точках погрузки/ленте (сейчас машины в одной очереди рендерятся в одной мировой точке без разнесения) — существующее ограничение, не в рамках этой задачи.
